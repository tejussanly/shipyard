Infrastructure as Code

Servers defined in files, reviewed like code.

Lesson

Clicking around a cloud console is slow and impossible to repeat exactly. Infrastructure as Code (IaC) describes servers, networks and databases in text files that live in git.

Terraform is the most popular tool. You write .tf files declaring what you want, run `terraform plan` to preview the changes, then `terraform apply` to make them happen.

Because infrastructure is now code, it gets reviews, history, and can be rebuilt identically for dev, staging and production.

Key points

  • Declarative .tf files
  • init → plan → apply
  • State tracks reality
  • Same code, many environments

Practise in the terminal

This is a simulated Linux machine with real commands: files, git, docker, kubectl, terraform, aws and more. Type a command and press Enter, or click the suggestions below in order. Nothing touches a real computer.

  • cat main.tf Infrastructure described in code
  • terraform plan Fails: not initialised
  • terraform init Download the AWS provider
  • terraform validate Check the syntax
  • terraform plan Preview the changes
  • terraform apply -auto-approve Create it
  • terraform state list What Terraform manages
  • terraform output Outputs (IP, bucket)
  • aws s3 ls The bucket really exists
  • sed -i 's/t3.micro/t3.small/' main.tf Change the instance size
  • terraform plan See the in-place update
  • terraform destroy -auto-approve Tear it all down
