CI/CD pipelines

From git push to production, automatically.

Lesson

Continuous Integration (CI) means every change is automatically built and tested as soon as it is pushed, so bugs are caught in minutes rather than weeks.

Continuous Delivery / Deployment (CD) takes a change that passed CI and ships it: to a staging environment first, then to production, sometimes after a manual approval.

A pipeline is a series of stages (checkout → install → test → build → deploy). If any stage fails, the pipeline stops and nothing broken reaches users.

Key points

  • CI = build + test every change
  • CD = ship what passed
  • Stages run in order
  • A failed stage stops the line

Practise in the terminal

This is a simulated Linux machine with real commands: files, git, docker, kubectl, terraform, aws and more. Type a command and press Enter, or click the suggestions below in order. Nothing touches a real computer.

  • cat .github/workflows/ci.yml The CI pipeline definition
  • npm test Fails: dependencies missing
  • npm install Install dependencies
  • npm test Run the tests
  • npm run build Build the app
  • gh run list Recent pipeline runs
  • gh run view 11842984 Why did this run fail?
  • echo "// BUG" >> src/app.js && npm test Break a test on purpose
  • git commit -am "Oops" && git push Push the broken code
  • gh run list CI catches it
  • gh run view See the failed step
  • git reset --hard HEAD~1 && npm test Undo the bad commit
