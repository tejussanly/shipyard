Kubernetes

Running many containers without babysitting them.

Lesson

Once you have dozens of containers across many machines, you need something to schedule them, restart them when they crash and scale them with traffic. That is Kubernetes (K8s).

The core objects: a Pod runs one or more containers; a Deployment keeps N copies of a Pod running and handles rolling updates; a Service gives those Pods one stable address.

You describe the desired state in YAML and apply it. Kubernetes continuously works to make reality match what you declared.

Key points

  • Pod → Deployment → Service
  • Desired state in YAML
  • Self-healing & scaling
  • kubectl is the CLI

Practise in the terminal

This is a simulated Linux machine with real commands: files, git, docker, kubectl, terraform, aws and more. Type a command and press Enter, or click the suggestions below in order. Nothing touches a real computer.

  • kubectl get nodes Machines in the cluster
  • kubectl get pods Running pods
  • kubectl get deployments Deployments
  • kubectl scale deployment shipyard --replicas=4 Scale out
  • kubectl get pods Now there are 4
  • kubectl delete $(kubectl get pods -o name | head -n 1) Kill a pod…
  • kubectl get pods …Kubernetes replaces it
  • cat deployment.yaml Desired state as YAML
  • kubectl apply -f deployment.yaml Apply it
  • kubectl set image deployment/shipyard app=shipyard:2.0 Release a new version
  • kubectl rollout history deployment/shipyard Release history
  • kubectl rollout undo deployment/shipyard Roll back
  • kubectl get svc Services
