Scripting & automation

If you do it twice, script it.

Lesson

Automation is the heart of DevOps. A bash script strings commands together so a task runs the same way every time, on any machine, without someone remembering the steps.

Scripts use variables, if-statements, loops and exit codes. An exit code of 0 means success; anything else means failure. CI tools use exactly this to decide if a step passed.

Start scripts with `set -euo pipefail` so they stop on the first error instead of carrying on silently.

Key points

  • #!/usr/bin/env bash
  • Exit code 0 = success
  • set -euo pipefail
  • Cron for schedules

Practise in the terminal

This is a simulated Linux machine with real commands: files, git, docker, kubectl, terraform, aws and more. Type a command and press Enter, or click the suggestions below in order. Nothing touches a real computer.

  • ls -l See which scripts are executable
  • cat deploy.sh Read a script
  • ./deploy.sh Run it (permission denied)
  • chmod +x deploy.sh && ./deploy.sh Fix and run
  • echo $? Exit code of the last command
  • ./hello.sh Script with variables and $(…)
  • NAME=Tejus; echo "Hi $NAME" Variables
  • for i in 1 2 3; do echo "step $i"; done A loop
  • if [ -f config.env ]; then echo found; fi An if-statement
  • cat config.env | grep PORT Pipe output into grep
  • crontab -l Scheduled jobs
  • ./backup.sh && ls ~/backups Run a backup, then check it
