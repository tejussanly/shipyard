Docker & containers

“Works on my machine” → works everywhere.

Lesson

A container packages your app with everything it needs (runtime, libraries, config) so it runs the same on your laptop, in CI and in production.

A Dockerfile is the recipe. Building it creates an image; running an image creates a container. Images are pushed to a registry (Docker Hub, GHCR, ECR) so servers can pull them.

Containers are lighter than virtual machines because they share the host’s kernel instead of booting a full OS. This very project ships with a Dockerfile, so you can try it.

Key points

  • Dockerfile → image → container
  • Push images to a registry
  • -p maps ports
  • Multi-stage builds keep images small

Practise in the terminal

This is a simulated Linux machine with real commands: files, git, docker, kubectl, terraform, aws and more. Type a command and press Enter, or click the suggestions below in order. Nothing touches a real computer.

  • docker images Images on this machine
  • cat Dockerfile The recipe
  • docker build -t shipyard:1.0 . Build an image
  • docker run -d -p 8080:80 --name web shipyard:1.0 Run it as a container
  • docker ps Running containers
  • curl localhost:8080 Visit the site in the container
  • docker logs web Container logs
  • docker exec web ls /usr/share/nginx/html Run a command inside it
  • docker run alpine echo "hi from alpine" A one-off container
  • docker stop web && docker ps -a Stop it
  • docker rm web Remove it
