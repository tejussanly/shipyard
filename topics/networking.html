Networking basics

How requests actually reach your app.

Lesson

Every service talks over the network. An IP address identifies a machine, a port identifies a program on it (HTTP 80, HTTPS 443, SSH 22), and DNS turns names like example.com into IP addresses.

HTTP is a request/response protocol: a client sends a method (GET, POST…) to a path and gets back a status code. 2xx means success, 4xx means the client did something wrong, 5xx means the server failed.

Load balancers spread traffic across several servers, and firewalls / security groups decide which ports are open to whom.

Key points

  • IP + port = where
  • DNS = name → IP
  • HTTP status codes
  • Load balancers & firewalls

Practise in the terminal

This is a simulated Linux machine with real commands: files, git, docker, kubectl, terraform, aws and more. Type a command and press Enter, or click the suggestions below in order. Nothing touches a real computer.

  • ping -c 3 google.com Is the host reachable?
  • curl -I https://example.com Fetch only the HTTP headers
  • curl https://api.github.com/users/tejus Call a JSON API
  • dig example.com +short DNS lookup
  • nslookup github.com Another DNS lookup
  • cat /etc/hosts Local name overrides
  • ss -tulpn Which ports are listening?
  • curl localhost Talk to nginx on port 80
  • sudo systemctl stop nginx Stop the web server…
  • curl localhost …and see the request fail
  • ip a Network interfaces and IPs
  • traceroute example.com The path packets take
