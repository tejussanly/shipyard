Linux & the shell

Every server you deploy to is almost certainly Linux.

Lesson

Linux runs most of the world’s servers, containers and cloud machines, so a DevOps engineer lives in the terminal. The shell (usually bash) lets you move around the file system, inspect processes, read logs and automate anything you can type.

Everything is a file: configs live in /etc, logs in /var/log, your home is ~. Permissions decide who can read (r), write (w) or execute (x) a file, for its owner, its group and everyone else.

Processes are running programs. You list them with ps or top, stop them with kill, and manage long-running services with systemctl.

Key points

  • Navigate: pwd, ls, cd
  • Inspect: cat, less, tail -f
  • Permissions: chmod, chown
  • Services: systemctl

Practise in the terminal

This is a simulated Linux machine with real commands: files, git, docker, kubectl, terraform, aws and more. Type a command and press Enter, or click the suggestions below in order. Nothing touches a real computer.

  • pwd Where am I?
  • ls -la List all files with details
  • cat notes.txt Read a file
  • mkdir -p projects/demo && cd projects/demo Make folders and move into them
  • echo "hello" > hello.txt Write text into a file
  • cd ~ && ./deploy.sh Try to run a script (it will fail)
  • chmod +x deploy.sh Make the script executable
  • ./deploy.sh Run it again
  • grep ERROR logs/app.log Find errors in a log
  • ps aux List running processes
  • systemctl status nginx Check a service
  • tail -n 5 /var/log/syslog Last 5 lines of the system log
  • df -h Disk space
