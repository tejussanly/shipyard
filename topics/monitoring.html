Monitoring & observability

Know it’s broken before your users do.

Lesson

Shipping isn’t the end. You need to know whether the app is healthy. Observability rests on three pillars: metrics (numbers over time), logs (events) and traces (a request’s path through services).

Prometheus collects metrics, Grafana draws dashboards from them, and alerting rules page someone when, say, the error rate stays above 5% for five minutes.

Good teams track a few key signals: latency, traffic, errors and saturation (the “four golden signals”), and agree on targets called SLOs.

Key points

  • Metrics, logs, traces
  • Prometheus + Grafana
  • Alert on symptoms
  • Four golden signals

Practise in the terminal

This is a simulated Linux machine with real commands: files, git, docker, kubectl, terraform, aws and more. Type a command and press Enter, or click the suggestions below in order. Nothing touches a real computer.

  • kubectl top nodes CPU and memory per node
  • kubectl top pods CPU and memory per pod
  • kubectl get pods -n monitoring Prometheus and Grafana
  • curl "localhost:9090/api/v1/query?query=up" Which targets are up?
  • curl -s localhost:9090/api/v1/alerts | jq .data.alerts Firing alerts
  • cat alerts.yml Alert rules
  • kubectl logs deploy/shipyard | grep ERROR Find the errors behind the alert
  • curl localhost:3000/api/health Is Grafana healthy?
  • systemctl status prometheus The Prometheus service
  • cat prometheus.yml What Prometheus scrapes
